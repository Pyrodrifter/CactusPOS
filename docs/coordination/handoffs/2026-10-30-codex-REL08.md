  original receipts remain void and retained. Historical-day review is read-only here; existing Orders still
  supports corrections recorded today. Payment-method changes now ask the operator to verify actual tender
  transactions rather than incorrectly instructing a refund on the newly selected terminal method.
- Cash drawer panel: owner cash-in/out, positive amount and required reason; opening float is a cash-in every
  morning. Server records business date, staff id/name, timestamp and UUID. No hardware action is automatic.
  **Open drawer** appears only with configured printer/drawer; practice keeps physical hardware off.

  replace/update/delete path. Wrong entries are offset once with equal opposite entries, preserving originals.
  Entire movement/audit/amount-bound validation is one transaction. Audit records trigger backup detection.
- Cash request is saved locally before sending. Read-only lookup recovers a committed reply; explicit retry
  retains the original key/body. Reusing a key with different contents is refused. UI says not to move cash
  again. Draft namespace separates staff, database and practice/live mode.

  summary/journal. Expected drawer = sales cash + cash-in − cash-out. Existing sales-only cash field and legacy
  count API remain compatible. New UI supplies whole-drawer basis and a report revision; stale closes fail
  before a Z number is allocated. Stored Z snapshots retain basis and cash journal; later changes flag reclose.

  staff. EN/NL manuals, screenshots and deployment count instructions updated. No new dependency.

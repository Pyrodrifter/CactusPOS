# Handoff: UX17 — kitchen lock and one-tap kitchen
- Agent: claude   Date: 2026-10-30   Branch: claude/amazing-ramanujan-kne4ff

Owner request (after UX15/UX16): "add the auto lock kitchen setting", and another kitchen workflow because the
three-step board "seems tedious and we are wasting unnecessary space".

## What changed
- **One-tap kitchen (new default, `apps/kitchen/`).** One board of everything still to cook (New and Preparing
  together), oldest first, dealt into as many 300 px columns as fit (1 2 3 / 4 5 6), so no column is ever empty
  and short tickets leave no gap. One deliberate tap on a ticket (or its slim **Ready** bar) marks it ready; it
  skips Preparing, which the API already allowed and the pickup board never distinguished. Ready orders shrink to
  number chips in a **Ready** strip in the sticky header (with the tab name); a tap on a chip = collected. Undo
  covers both taps as before. Status logic moved into `useStep()`, shared by tickets and chips.
- **Three steps** stays available per device (Screen tools > Kitchen screen > Three steps), unchanged.
- **Lock to the kitchen** (Screen tools > Kitchen screen). Per device: the router only knows `/kitchen` (every other
  address and sign-in lead there), the top bar with Order/Admin/Pickup is not rendered, and a Screen tools button
  sits at the start of the kitchen header (the way back out). Survives restarts and new sign-ins (localStorage).
- **Device preferences** (`lib/display.ts`): `useDevicePrefs()` / `setDevicePref()` for `kitchenLock` and
  `kitchenFlow`, reactive across the shell, router and kitchen, and across tabs. `SCREEN_TOOLS_EVENT` opens Screen
  tools from a screen. On the kitchen, the Kitchen screen settings come first in Screen tools.
- Tests: `e2e/kitchen-flow.mjs` (new): one tap to ready, chip to collected, undo, lock keeps to the kitchen from
  `/pos`, `/admin` and `/login` and fits the four sizes, Three steps, unlock. `e2e/kitchen-taps.mjs` now expects a
  short tap to go to Ready.
- Manual EN + NL: Kitchen section rewritten for one tap and the Ready strip, Three steps described as the option;
  chapter 8 gains "Lock it to the kitchen". Pictures retaken: kitchen and Screen tools only.

## Contracts touched
None. Same status route; `sent -> ready` was already accepted by `setStatus`.

## How to verify
```bash
npm run check
npm run e2e
```
All 8 browser checks pass. By hand: Kitchen, tap a ticket once, it jumps to the green Ready strip; tap the number.
Screen tools > Lock this screen to the kitchen: the top bar disappears, `/pos` and `/admin` open the kitchen; the
sliders button at the top left of the kitchen opens Screen tools to switch it off.

## Gotchas / decisions
- **Who marks collected.** In the one-tap kitchen, Recall exists only as Undo (a few seconds). If the counter, not
  the cook, should mark orders picked up, that is a next step (the counter's Orders list has no such button yet).
- **Tablets set up before this change** switch to one tap by themselves (it is the default). Three steps is one tap
  away in Screen tools.
- The lock is a guard against accidents, not security: anyone can switch it off in Screen tools. Admin still needs
  the owner's PIN as before.
- Round-robin columns keep reading order but move later tickets to another column when one leaves; the 350 ms
  settle guard from UX16 covers taps during that shift.
- Manual pictures were taken with Chromium on Linux (font differs slightly from the Windows ones); retake on the
  laptop with `node scripts/make-manual.mjs --shots` before a release.

# Handoff: UX12 — personal receipts (lettering, text looks, richer editor)
- Agent: claude   Date: 2026-10-10   Branch: agent/claude/receipt-editor

Owner request: "make the receipt editor a better editor so the receipts can be more personal, maybe different fonts
and others". Builds on UX09's versioned receipt designs; nothing in UX09 was removed.

## What changed
- **Lettering in any font.** A receipt printer has one typeface, but it prints pictures. The editor draws a line in
  a font of the device it runs on (22 were found on the owner's Windows PC; a font file can be added too) and stores
  the result as black and white dots in the design. Available for the business name and for each of the owner's own
  lines. `packages/web/src/apps/admin/receipt-editor/lettering.ts`.
- **Printer text looks.** Size (small, normal, tall, wide, large, extra large), bold, underline and white on black
  for the business name, the line above it, the line under the header, the closing line and each own line. These are
  the printer's built-in styles, so they print crisp and fast.
- **Own lines** (was "extra text blocks"): up to 6 instead of 4, each above the items or below the total.
- **More dividers** (double, dots, stars, waves), an **extra large order number**, a **bigger logo** (up to the
  full paper width, three sizes) and a **closing picture** under the footer.
- **Preview true to the paper.** The printable HTML page is now a character grid exactly as wide as the paper
  (48 or 32 characters), so a line wraps in the preview where it wraps on the printer. The editor shows it enlarged.
- Editor regrouped: Top of the receipt, Your own lines, The order, End of the receipt, Dividing lines, Paper, History.
- Files: `shared/src/receiptDesign.ts`, `receipt/src/{blocks,build,renderText,renderHtml,renderEscPos}.ts`,
  `receipt-editor/{ReceiptEditor.tsx,lettering.ts,receipt-editor.css}`, tests, `e2e/receipt-editor.mjs`.

No new dependency, no font files in the repository, nothing fetched from the internet.

## Contracts touched
`contracts/service-and-receipts.md`, section "Personal receipts (UX12)". `DocumentDesign` gained optional fields only
(`nameStyle`, `nameArt`, `titleStyle`, `subtitleStyle`, `footerStyle`, `closing`; messages: `size`, `underline`,
`inverse`, `position`, `art`), `numberSize` and `separator` gained values, messages go up to 6, pictures up to
576 x 400 dots. Block types in `@cactus/receipt`: text blocks take `size` (six values), `underline`, `inverse`;
raster blocks take `alt`; `Line.large` became `Line.size`. No route changed.

## How to verify
```sh
npm run check     # 232 tests in 22 files
npm run e2e       # 4 browser checks; receipt-editor.mjs is the new one
```
`e2e/receipt-editor.mjs` in headless Edge: picks lettering for the name, checks the preview holds a picture of
"Cactus Blue", adds a wide line above the items and a lettering line below the total, wave dividers, extra large
order number, measures touch targets at 1180 and 390 px, publishes, then pays a real order and finds the lettering
on its receipt. `receipt/src/personal.test.ts` pins the printer bytes for every look and proves an old design emits
none of the new commands.

**Not verified: a real printer.** The commands are standard ESC/POS (`ESC M`, `GS !`, `ESC -`, `GS B`, `GS v 0`)
and pictures already printed this way for the logo, but no physical printer has been tried yet (Q2 is still open).
Cheap clones sometimes lack the narrow font or white-on-black; "Test receipt printer" in the editor shows it at once.

## Gotchas / decisions
- **Fonts live on the device that edits.** Lettering is a picture once saved, so it prints the same everywhere, but
  to *change* it you need a device that has the font. On one that does not, the editor says so, leaves the picture
  alone, and only redraws (in a font it has) when you change that line.
- The business name must be on the paper. Name lettering is used only while it spells the name the order was sold
  under; after a rename the receipt prints the name as text and the editor asks to draw it again.
- Lettering shows words as typed: `{{order}}` and friends only work in printer letters.
- A design is stored whole in each version, pictures included: a dressed-up design is some tens of kilobytes per
  published version. The request limit is 1 MB.
- The paper width in the design decides how wide lettering is drawn; the printer's own column setting still decides
  what fits. A picture made for 80 mm is scaled down on a 58 mm printer (nearest dot, so thin strokes may break up).
- Browser printing (the fallback without a receipt printer) is now true to size: letters are 3 mm tall as on thermal
  paper, where they used to be about a third larger and wrapped earlier than the printer does.

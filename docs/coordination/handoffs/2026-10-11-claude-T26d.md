# Handoff: T26d — setup program, user manual, release 0.2.0
- Agent: claude   Date: 2026-10-11   Branch: agent/claude/REL01

Owner request (2026-10-11): release CactusPOS with an easy installer that also takes care of what it needs, so
their mother can install it herself, with a detailed manual on setting it up, and put it on GitHub.

Until now a release was a zip with `Install CactusPOS.bat`: unzip, choose a folder, trust a console window. That
route stays (B in `ops/install.md`). New is one file to double-click.

## What changed
- **`ops/windows/setup.iss`** (new): the setup program, built with Inno Setup 6. English and Dutch. Language,
  Next, Next, the firewall question, Finish. Installs for the signed-in Windows user into
  `%LOCALAPPDATA%\Programs\CactusPOS` (no administrator rights except the one firewall question), registers under
  *Settings → Apps* for removal, checks Windows 10 1809+ / 64-bit and says so when neither Edge nor Chrome is
  there. An update (running a newer setup) stops the running till first and clears `node_modules` and `packages`
  so nothing of the old version lingers. Removing keeps the sales data.
- **Everything it needs is inside**: the ready-made package of `scripts/make-redist.mjs` (program, production
  libraries, built screens, its own `node.exe`, now also the manual). No Node.js, npm or internet on the till.
- **`ops/windows/install.ps1`**: still does settings and shortcuts for all three routes. New: `-ResultFile` (port
  and firewall state for the setup program), Start menu entries **Connect a tablet or phone**, **Restore a
  backup**, **Manual (English)**, **Handleiding (Nederlands)**. `firewall.ps1 -Check` (read-only), `stop.ps1`
  (stops the server of one program folder; only ever a `node.exe` from that folder's own `runtime\node`),
  `restore.ps1 -Choose` (newest backup, or pick a file in a file window).
- **`ops/app/launch.mjs --addresses`** (+ `addressesText()` in `lib.mjs`, tests): shows in a window what to type
  on a tablet. Until now that was "open cmd and run node ...", which no till operator will do.
- **User manual**: `docs/manual/manual.en.html`, `manual.nl.html`, `manual.css`, pictures in `docs/manual/img`.
  23 pages each: what you need, installing (with the Windows warnings), first-time setup, selling, tabs and
  corrections, kitchen and pickup, connecting a tablet, closing the day, backups and restore, updating and
  removing, a problems table, and one page to keep by the till. `scripts/make-manual.mjs` prints both to PDF with
  the Edge or Chrome on the build computer; `--shots` retakes the screen pictures from a throwaway till
  (`docs/manual/shots.mjs`); `docs/manual/setup-shots.ps1` retakes the pictures of the setup's own windows.
- **`scripts/make-setup.mjs`** (`npm run package`): package folder, zip, manual PDFs, setup program and
  `SHA256SUMS.txt` in `dist/redist`. `npm run manual` builds only the PDFs.
- Version **0.2.0** (`package.json`, `packages/server/package.json`, lock file). `ops/install.md` and the README
  describe the three routes and have a "Building a release" section.

## New dependency
No npm package. The **build** computer needs Inno Setup 6 (`winget install --id JRSoftware.InnoSetup -e`; I
installed 6.7.3 for this Windows user). Why: it is the standard free tool for a Windows setup program and brings
the wizard, the Dutch translation, the uninstaller and the update handling; writing those by hand would be a
second product. Its licence allows any use, commercial included. Nothing of it runs on the till except the setup
and uninstaller it generates.

## How to verify
- `npm run check` (252 tests; 3 new for `--addresses`) and `npm run e2e`.
- `npm run package`, then:
  `powershell -ExecutionPolicy Bypass -File docs\manual\setup-shots.ps1 -Setup dist\redist\CactusPOS-Setup-0.2.0.exe -Lang en -Finish click -OutDir %TEMP%\shots`
  It runs the real setup as a test copy (own folders and port, no firewall, no entry under Apps), clicks through
  it, presses Finish, expects the till to come up, checks the shortcuts, removes the copy and checks that the data
  folder survived.
- By hand, the real thing: double-click `dist\redist\CactusPOS-Setup-0.2.0.exe`. This is the one way to see the
  Windows permission question.

## Gotchas / decisions
- **Unsigned.** A downloaded copy gets the SmartScreen warning; a copy from a USB stick does not. Signing costs a
  yearly fee: QUESTIONS Q32.
- **The repository is private**, so the Releases page is no use to someone without a GitHub account that has
  access: QUESTIONS Q31. The manual says "the file you were given" for that reason.
- The firewall question is asked by the setup window itself (`ShellExec runas`), not by `install.ps1` hidden in
  the background: a permission prompt from a hidden grandchild process tends to open minimised in the taskbar,
  and the setup would look frozen. `install.ps1` is called with `-SkipFirewall` and reports whether a rule is
  needed.
- A silent install (`/VERYSILENT`) does not ask for the firewall rule and does not start the till.
- The Start menu entries and the two windows behind them (addresses, restore) are English in both languages; the
  Dutch manual names them as they are and says what they mean.
- Inno Setup 6.7 does not rename "Next" to "Install" on the last page when the "ready" page is disabled; the
  manual says Next.
- Chromium prints an inline box with a border at the old place when its paragraph moves to the next page. In
  `manual.css` the button labels are `inline-block` for that reason. Checked: no empty label boxes in either PDF.
- `setup.iss` must stay plain ASCII (no byte order mark, so it is read in the Windows code page). The Dutch
  messages are worded to need no accents.
- Manual pictures are committed (4.8 MB) and retaken on purpose, not on every build. **When a button is renamed
  or a screen changes, the manual is wrong until someone updates `docs/manual`**: see REQUESTS R20.

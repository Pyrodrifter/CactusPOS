## What changed
- Isolated practice database under `data/practice/practice.sqlite`, with separate sessions, service, WebSocket
  hub, receipt counters, reports and local backups. First use copies current business/service/menu/tax/staff/
  receipt setup only. Network printer transport, drawer, bookkeeping writes/CSV and external backup settings
  are blocked server-side. HTML receipts/reports are stamped PRACTICE/OEFENEN. Explicit browser receipt
  printing still offers a stamped practice receipt; there is no automatic hardware printing.
- Explicit practice entry under Screen tools and Admin → Ready to open. Yellow mode banner and confirmation
  before returning to live. Payment sheets also show PRACTICE/OEFENEN so the modal cannot obscure the mode.
  Practice kitchen/pickup/menu-board paths retain `/practice`; live and practice sockets never share orders.
- Device drafts persist by staff/database instance/mode: cart, notes, tab target, original send body/key and
  unresolved payment order. Read-only recovery looks up the original send or order. No automatic replay;
  explicit retry uses the frozen original key/body. Already-paid orders cannot be paid from recovery.
  Acknowledged recovery resets the next order's identity (covered by identical-order regression).
- Owner opening checklist checks server, kitchen connection count, optional printer TCP socket, backup age/
  external-copy status, business/CRIB completeness, used tax-category verification flags and example PINs.
  It prints nothing and does not claim to verify paper/cutter or tax legality.
- Android 0.2.0 persists practice on reopen/reconnect/same-server screen changes; native title says PRACTICE.
  Older APKs are blocked from practice. Signed APK retains the existing key and updates over 0.1.0.
- EN/NL instructions and manual pictures updated. `make-manual --shots-only` refreshes pictures without
  rebuilding release PDFs. Sunday/deployment instructions distinguish current source from the old installer.

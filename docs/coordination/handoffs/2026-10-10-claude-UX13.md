# Handoff: UX13 — QR codes on the receipt (WiFi and links)
- Agent: claude   Date: 2026-10-10   Branch: agent/claude/receipt-qr

Owner request, right after UX12: "and QR codes and WiFi on the receipt".

## What changed
- **The till draws its own QR codes.** New `packages/receipt/src/qr.ts`: byte mode, error correction level M,
  sizes 1 to 20 (up to 666 bytes). No library at run time.
- **Printed as a picture.** A `qr` block is now laid out as a raster, like the logo, in whole printer dots per
  square and shrunk in whole dots to fit the paper. Before, the ESC/POS renderer sent the printer's own QR command
  (`GS ( k`), which not every printer has, and the HTML page showed the placeholder "[QR]". Now the preview, the
  browser print and the thermal print all show the same squares.
- **Design:** `DocumentDesign.codes` (up to 3), each a `wifi` code (network name, password, security, optional
  name and password as text under it) or a `link` code (a web address or any short text), with a caption, three
  sizes and a place above the items or below the total.
- **Editor:** a "QR codes" section with "Add a WiFi code" and "Add a link code".
- Files: `shared/src/receiptDesign.ts`, `receipt/src/{qr,blocks,build,renderText,renderHtml,renderEscPos}.ts`,
  `receipt-editor/ReceiptEditor.tsx`, tests, `e2e/receipt-editor.mjs`.

**New development dependency: `jsqr` 1.4.0** (Apache-2.0, no dependencies of its own). Why: the tests read our QR
codes back with a decoder written by other people, so "it scans" does not rest on our encoder agreeing with itself.
It is used in tests only and is not installed on a till (`make-redist.mjs` installs without development packages).
After pulling, run `npm install` once.

## Contracts touched
`contracts/service-and-receipts.md` ("QR codes (UX13)"). `DocumentDesign.codes` is new and optional (default `[]`).
In `@cactus/receipt`: the `qr` block takes `scale`; `layout()` no longer returns a `qr` item (it returns a `raster`
whose `alt` is `QR <data>`); new exports `qrMatrix`, `qrRaster`, `QR_MAX_BYTES`, `QR_QUIET`. The printer test page
prints its QR as a picture too.

## How to verify
```sh
npm install       # once, for jsqr
npm run check     # 239 tests in 23 files
npm run e2e       # 4 browser checks
```
- `receipt/src/qr.test.ts`: jsQR reads back a web address, an Instagram link, WiFi details with awkward characters
  and accented text; every one of the 20 code sizes; and a long text printed for 58 mm paper.
- `receipt/src/personal.test.ts`, "QR codes on a design": placement, caption, WiFi details in words (English and
  Dutch), open networks, empty codes left out, the preview's SVG.
- `e2e/receipt-editor.mjs`: adds a WiFi code and a link code in the editor, finds both in the preview, publishes,
  and finds the WiFi code on the receipt of a real paid order.

**Not verified:** a phone camera on real thermal paper. The dots sent to the printer are the ones jsQR decodes in
the tests, at 4, 6 or 8 printer dots per square (0.5 to 1 mm), which is comfortably within what phones read; a worn
print head or pale paper is the usual cause when a printed code will not scan, and the large size helps then.

## Gotchas / decisions
- **The WiFi password is printed for every guest** and stored in the design (owner-only route, in backups). The
  editor says so. Use the guest network, not the one the till and tablets are on.
- A WiFi code with security "open" ignores any password typed earlier.
- Link codes hold exactly what was typed. A phone only opens it as a web page when it starts with `https://`.
- Text is stored in UTF-8 without an ECI marker; phones assume UTF-8, which is why accents and emoji read back.
- The size is dots per square, so a longer text makes a physically bigger code. On 58 mm paper a long text is drawn
  with fewer dots per square instead of being cut off.

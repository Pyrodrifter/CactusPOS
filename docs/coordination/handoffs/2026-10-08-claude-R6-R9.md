## R9 / T03 — database
- `db.ts`: versioned migrations (`PRAGMA user_version`, one transaction each, newer-than-program refused, handle closed on failure). v1 = original tables, v2 = ledger hardening.
- Triggers that hold on any connection: no REPLACE/UPDATE/DELETE on `order_events`, `payments`, `audit_log`; orders cannot be replaced or deleted, identity and issued receipt numbers are fixed, payments in `data` cannot shrink; counters only go up. `recursive_triggers` is also on.
- New append-only `payments` table (complete payment incl. reference, tip, receipt number, staff); v2 backfills it from existing orders.
- Every event now stores the full order snapshot. `orderFromEvents`, `verifyLedger`, `repairOrder` on `PosService`.
- `busy_timeout` 5 s; "database is locked" maps to HTTP 503.
- Checked-in tests: REPLACE on orders/events/payments (incl. a raw connection with recursive triggers off), payment removal, receipt/identity rewrite, rollback after counter allocation, lock contention between two connections, **four processes paying 12 orders concurrently** (numbers exactly 1..12), fresh/repeat/upgrade-from-v1/newer/failed migration.
- The service no longer upserts orders: explicit INSERT on create, UPDATE afterwards.
